===============================================================================
 WhatsApp Embedded Signup (WABA one-click connect) — Setup Reference
===============================================================================

The official Meta self-onboarding flow (the same approach BSPs like Gupshup /
Wati use). The end user clicks "Continue with Facebook", logs into Meta, and
picks or creates their WhatsApp Business Account (WABA) + phone number inside
Meta's embedded popup. Our backend then auto-fetches the API credentials — no
manual token copying.

It is CONFIG-DRIVEN and DORMANT until the Meta credentials are added:
  - With no credentials, the UI shows a "not enabled — use manual" state and
    the endpoint refuses cleanly.
  - Adding the Meta env vars + restarting the backend activates it. No code
    changes needed.


-------------------------------------------------------------------------------
 FILES — WHAT EACH ONE HOLDS / DOES
-------------------------------------------------------------------------------

BACKEND
-------
1) backend/src/infra/config.ts
   Holds the Meta env vars (all OPTIONAL — feature stays off until set):
       META_APP_ID
       META_APP_SECRET
       META_CONFIG_ID
       META_GRAPH_VERSION      (default: v22.0)
       META_REDIRECT_URI
       WHATSAPP_REGISTER_PIN   (default: 000000)

2) backend/src/modules/whatsapp/connection/embeddedSignup.ts
   The whole Meta flow (functions listed below).

3) backend/src/modules/whatsapp/connection/service.ts
   Existing connection store. ConnectionInput was extended with `status` +
   nullable fields so signup can write credentials. upsertConnection persists
   them into the chatbot's Connection row.

4) backend/src/modules/whatsapp/connection/routes.ts
   The two new HTTP endpoints (listed below).

FRONTEND
--------
5) frontend/src/app/chatbots/[id]/settings/EmbeddedSignup.tsx
   The "Continue with Facebook" button, Facebook JS SDK loader, popup launch,
   the message event listener, and the 4-step stepper UI.

6) frontend/src/app/chatbots/[id]/settings/page.tsx
   Renders <EmbeddedSignup> at the top; keeps the manual credential form below
   as a fallback ("Or configure manually").


-------------------------------------------------------------------------------
 FUNCTIONS — embeddedSignup.ts
-------------------------------------------------------------------------------

- isEmbeddedSignupConfigured()
      Returns true only if App ID + App Secret + Config ID are all present.
      Gates the whole feature.

- exchangeCodeForToken(code)
      Trades Meta's short-lived (~60s) auth code for the long-lived BISU
      access token. Backend-only; uses the app secret.

- getWabaDetails(wabaId, token)
      Reads the WABA name (for display).

- getPhoneDetails(phoneNumberId, token)
      Reads the display phone number + verified name (for display).

- subscribeApp(wabaId, token)
      Subscribes your app to the WABA's webhooks.
      MUST run before registering, or webhooks won't arrive.

- registerPhoneNumber(phoneNumberId, token)
      Registers the number for Cloud API using the PIN.
      Safely ignores "already registered".

- completeEmbeddedSignup(chatbotId, { code, wabaId, phoneNumberId })
      The orchestrator: runs all of the above in order, then saves everything
      to the chatbot's Connection with status: CONNECTED.

- EmbeddedSignupError
      Typed error so the route returns a clean message instead of a 500.


-------------------------------------------------------------------------------
 ENDPOINTS — routes.ts
-------------------------------------------------------------------------------

GET  /api/chatbots/:id/connection/meta-config
     Returns { enabled, appId, configId, graphVersion } so the frontend can
     boot the FB SDK. NEVER returns the app secret.

POST /api/chatbots/:id/connection/embedded-signup
     Receives { code, wabaId, phoneNumberId } from the frontend and calls
     completeEmbeddedSignup.


-------------------------------------------------------------------------------
 END-TO-END FLOW
-------------------------------------------------------------------------------

1. Settings page loads -> asks meta-config -> if enabled, loads FB SDK.
2. User clicks "Continue with Facebook" -> FB.login opens Meta's popup.
3. User logs in, picks/creates WABA + phone inside Meta's UI.
4. A message listener catches Meta's WA_EMBEDDED_SIGNUP "FINISH" event ->
   captures waba_id + phone_number_id. The FB.login callback gives the code.
5. Frontend POSTs code + waba_id + phone_number_id to embedded-signup.
6. Backend exchanges code -> token -> subscribes app -> registers phone ->
   saves the Connection. Done — credentials auto-provisioned.


-------------------------------------------------------------------------------
 TO GO LIVE (Meta-side setup, not code)
-------------------------------------------------------------------------------

1. Add these to the backend .env, then restart:
       META_APP_ID=...
       META_APP_SECRET=...
       META_CONFIG_ID=...
       META_REDIRECT_URI=https://yourdomain/...   (must match a registered
                                                    OAuth redirect URI)
       WHATSAPP_REGISTER_PIN=123456

2. Meta App must pass App Review for:
       whatsapp_business_management     (Advanced Access)
       whatsapp_business_messaging      (Advanced Access)
   plus Business Verification, and be in LIVE mode.
   Until then only admin/test users of the app can complete the flow
   (fine for development testing).

3. The deploy domain must be HTTPS and registered in the app's
   Allowed Domains / Valid OAuth Redirect URIs.
